## ③ 隔离反向判据（红/绿两侧）

**要证的一件事**：测试副本一个字节都没碰用户真实 `~/.magic`（读与写两面），**且这条判据抓得住**
「真去碰它」的行为。判据落在**行为**上，不落在日志上——实测本机 `sandbox-exec` 的 file-read
拒绝**不落**统一日志，拿日志当证据会得到一片空白，而空白跟「没有违规」长得一模一样。

八条，全绿（读数见 `证据/isolation.json`）：

| 判据 | 结果 |
| --- | --- |
| **绿**：带固定隔离根的副本，在「拒读拒写真实 `~/.magic`」的沙箱里照常起到 `app.ready` | ✓ |
| **红**：同一份包、同一套装置，**只把隔离根里的运行目录拒掉** ⇒ 起不到 ready（`app.error`：那个目录存不进去） | ✓ |
| **闸**：同一个沙箱里，一个故意的读者（`cat 真实 ~/.magic/config.json`）当场被拒 | ✓ |
| **闸**：同一个沙箱里，一个故意的写者当场被拒 | ✓ |
| **写面**：真实 `~/.magic` 前后快照逐条一致（42 条 · 0 处改动） | ✓ |
| 快照**非空**（空集相等不算证据：先证它有 42 条） | ✓ |
| **正控**：宿主自己报的 dataDir / base / config 与发现记录**四件全落在隔离根底下** | ✓ |
| **尺子自检**：快照比较器对「改一个字节」抓得住（按 SHA256 抓内容改动，不只看 mtime） | ✓ |

**关于工单那句「改前红」**：工单假定「隔离原来靠 dev 身份兜底，所以去掉它之前先证隔离还在」。
**这个假定不成立** —— 隔离从头到尾来自 `validationRoot` 那一支（`AppModel.init` 里三处第一支：
`selectedBase` / `userHome` / `defaults` 的 suite 名，都是 `validationRoot` 优先；另有独立
validation 身份 ＋ capability 文件）。故这里给的「红」不是「改前那份代码」，而是**同一份二进制上
换掉被拒的路径**：拿掉隔离根里那个运行目录，它当场起不来；留着它、只拒真实 `~/.magic`，它照常起来。
——同一把尺子量同一个被测对象，两次只差一个变量。

**没做的**：没有在「把 `isDevelopment` 加回去」的树上跑这一趟。「加回去」不改变那三处第一支，
按代码读它不构成变量；要真跑的话，那是另一份构建，且与本单「不许为让门变绿而弱化/加戏」同一条
——**没跑就不写成跑了**。
