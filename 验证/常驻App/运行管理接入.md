# 常驻运行管理接入

本文件供多智能体分支整合使用。宿主核心先在 `feat/resident-macos-app` 形成独立稳定提交，原生外观、通知和发行不属于此交付出口。没有主干合并或推送。

## 宿主收尾

`ManagerOptions.lifecycle` 三个出口属于同一条收尾责任链：

- `closeAdmission(): void` 同步持久关闭业务准入。管理者立即拒绝新活；此门抛错时保留关闭姿态，下一次 `stop()` 必须重试此门，不能绕过。
- `shutdown(): Promise<void>` 确认扩展侧收尾。它与宿主持有的执行者 TERM/KILL 和自有组回收并行；挂起或抛错不阻止物理回收，也不代表宿主已完成。失败可在同一宿主上重试。
- `affected(): Promise<readonly NativeWork[]>` 从持久业务事实给出受影响工作；有效协作等待即使没有执行者，也须计入退出影响。

`stop(why)` 只表示开始关闭，不是完成。只有 `waitUntilExit()` resolve，才能发送 `host.stopped`；原生端还要等 helper 进程实际退出才退出 App。stdin EOF 和明确 `host.shutdown` 共用此链。

## 单代资源确认

当前没有公开的单会话 Promise；`waitUntilExit()` 等整个宿主，不能用于等待某个执行者。`manager.ts` 的停止等待者已绑定同一 `RunRecord` 对象，协作等待者须沿用这条归属：

1. 真实 launcher 的 `onExit` 到达后设置 `executor.exited`，才进入 `retire`。socket close 本身仅触发停止升级，不能冒充进程退出。
2. `retire` 标记执行者已退、保留最近记录并通知窗口 detached；它不保证自有组已核销。
3. `afterEnd` 在没有自有组时可完成该代等待；有自有组时必须等 `reclaimRun(run)` 返回 `undefined` 且没有 `reclaimNote`。失败保留本代责任供重试。
4. 此后才调用协作侧 `executorExited(session, reason)` 并兑现按 `RunRecord` / `session + run.gen` 绑定的等待者，不以当前 session 的最新一代代替旧代。

协作执行记录的 `executionId` / `runId` 来自该执行者的 token。调用核销出口时必须保留这个 token；不能按 session 扫完全部 execution，旧代的重试不得结束新代记录。此接线由多智能体分支沿同一核销出口完成。

`run.gen` 是执行者代次；`NativeWork.gen` 是用户停止目标的版本，每次新输入或新轮次都会变化。两者不能互换。完整协作投影由协作侧按 `collaboration.originSessionId` 归并，含成员状态、事项与无执行者的有效等待；停止校验同一整项工作版本。协作侧负责 `collaboration-native.ts` 及 manager 的组合接线。

`projectWorks` 在异步读取会话目录之前同步固定运行状态与停止版本。查询途中换代不会把旧状态配上新版本，过期投影中的停止目标仍须由 `native.stop` 拒绝。

## 事件与只读边界

`turn.end.continues === true` 表示同一次交代的模型工具中间轮。仅 `reason === 'settled' && !continues` 产生单会话完成事项；协作整合还须排除普通成员独立完成通知，并等整体显式关闭、资源确证后生成整体完成事实。

hello、订阅、目录、历史及只读配置观察不创建执行者、不消费未读。没有可靠终端在场证据或具体用户查看动作时，真实 TUI 渲染也不自动标读；历史中的任意助手答复不能充当某条新完成事项的结果关联。原生明确展开具体事项使用具体 id 的 read，与 delivered 和审批答复相互独立。

## 验证入口

- `resident-manager.test.ts`：持久准入首次失败重试、扩展挂起时真实子进程 KILL、无确认不完成、原生停止目标过期、只读观察与 56 条真实历史分块。
- `resident-reclaim-order.test.ts`：socket 先断但 PID 仍活，执行者退出时自有组仍活，全部资源确认后才 `done`。反向只在内存恢复“socket close 即 retire”，精确失败于执行者仍活却已从当前代登记移除，不依赖超时。
- `host-runtime.test.ts` 与 `run-host-active.test.ts`：正常命令/生命管道 EOF 的空闲和待答真实进程链。
- 原生端、真实 TUI 与最终同版包证据分别记录，不能由这些定向用例代替整单验收。
